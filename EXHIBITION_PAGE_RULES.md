# Final Exhibit — Binding Design, Content, Motion, and Release Rules

**Status:** authoritative working standard for the entire `kilejones-alt/Final-Exhibit` repository. **Scope:** existing cinematic homepage (`index.html`), Three Eras overview (`entrance.html`), every exhibit room, and all 20 reserved future pages with English, Russian and Hebrew mirrors. This rulebook supplements `EXHIBIT_REQUIREMENTS.md` and `LANGUAGES.md`. If instructions conflict, preserve the already-approved visible text and artwork and require explicit editorial approval before changing either. Do **not** confuse this project with the separate StopAZ teaser.

## A. Mandatory cross-site rules — no exceptions

1. **Content fidelity.** Never silently write, paraphrase, shorten, replace, translate as final, or invent exhibition copy. Preserve approved human-authored text, punctuation, headings and links verbatim. Proposed editorial changes must be presented separately for approval. Draft Russian and Hebrew translations need qualified language review before public release.
2. **Historical image integrity.** No AI-generated or AI-altered exhibition images. Preserve existing archival images, cropping intent, attribution, licensing/permission tracking and artifact order. New artwork requires a known source and approved permission; historical imagery must not be misleadingly reconstructed.
3. **Museum aesthetic.** Dark gallery background (official cinematic root uses `#050505`; editorial pages use `#0a0a0a`), near-white type, black/white/grayscale art treatment and restrained low-intensity accents on interaction. No beige, colorful decoration or unrelated icons. Prioritize archival seriousness rather than a generic template look.
4. **Type.** Site headings use existing bundled **Caslon**, with Georgia fallback; body and supporting labels use existing **Source** family with safe fallbacks. Match framework/diagram typography to surrounding page rather than using a foreign raster font. Cyrillic and Hebrew must have legible script-appropriate fallbacks without changing hierarchy.
5. **Rhythm and spacing.** Center exhibitions within their established maximum widths (editorial sections up to 1440px; visual framework about 900–940px), with responsive `clamp()` gutters and intentional sectional gaps. Balance edges, card heights, headings and columns. No clipped words, forced mid-word breaks, horizontal document overflow, orphaned decorative lines or massive empty space.
6. **Reveal on scroll.** Content **arrives when scrolled into view**, not fully visible far in advance. Use `IntersectionObserver` with modest early trigger, gentle upward displacement, opacity/blur easing and modest stagger. Headings, paragraphs, figures, artwork, card blocks and diagrams are all in scope. Preserve reading flow and never hide content if JavaScript is unavailable or reduced motion is selected.
7. **Motion character.** Slow, deliberate, clearly noticeable but never immobilizing. Most editorial reveals are approximately 1.1–1.8 seconds; main framework drawing should resolve in roughly 3–4 seconds from entrance (not the old 10-second sequence). Lines/arrowheads draw rather than pop. Scroll performance must remain smooth and low-cost.
8. **Images on hover.** Art frames/cards lift noticeably (approximately 8–12px in the shared museum system; the three large entrance doors can lift more, consistent with existing art direction). A slight controlled brightness/depth increase is acceptable but no washed-out art. Images perform a subtle **5–6-second camera push**, currently approximately 5.5 seconds to 1.055× scale; never a sudden zoom. Keep image clipping inside the frame.
9. **Heading/subtitle hover.** On pointer/focus, titles, subtitles, captions, card labels and eligible controls lift and respond gently, without jumping downward or fighting the scroll reveal transform. Maintain keyboard `:focus-visible` parity; touch gets suitable feedback without pretending to support hover.
10. **Accessibility.** Semantic `main`, real headings, image alternative text, accessible buttons/links, sufficient dark-theme contrast, focus outlines, minimum comfortable touch targets, and `prefers-reduced-motion` accommodation. Audio is opt-in, respects play failures, and retains a real toggle state. No invisible interactive traps.
11. **Performance and resilience.** Use existing asset paths, native CSS/SVG where possible, font-display swap, lazy-load noncritical art when populated, stable aspect ratios, safe-area insets, `svh/dvh` viewport units, passive scroll handling and animation only on transform/opacity/stroke where feasible. An animation must degrade to readable static content without its script.
12. **Language mirrors.** Every content page has **English, Russian, Hebrew**, with matching number/order of sections, image references, links, interactive controls and timing. Hebrew has `lang="he" dir="rtl"`; diagram geometry may remain LTR while Hebrew language itself reads RTL. English, Russian and Hebrew are released as a coherent set, only after language approval.
13. **Navigation and metadata.** Keep real URLs and preserve expected page relationships, site icon, social image, canonical/hreflang on publicly ready pages. Avoid broken links and duplicate content. **Blank pages are noindex and unlinked** until explicitly approved for publication.
14. **QA hard gate.** Inspect real rendered pages, not source alone, at **320px, 360px, 390px, 412px, 768px, 1024px, 1280px, 1440px and wide desktop**, plus landscape, keyboard, touch where possible and reduced-motion mode. Verify before reveal, after reveal, 5–6-second hover, long text expansion, linked destinations, scroll overflow, smoothness and media state. Clearly separate source checks, screenshots, browser simulations and real hardware. Do not claim visual certification without it.
15. **Publishing discipline.** Build and check in a review branch; compare all changed files; preserve approved homepage and overview content unchanged unless authorized. No merge to main or live deployment before user preview/approval. The rulebook is not authorization to change existing copy or art.
16. **Do not treat blank pages as published content.** A reserved page is only a ready *shell*, with no visible title, text, placeholders, header, footer, images, navigation or controls, and no invented editorial content.

## B. Existing cinematic landing-page-specific rules (`index.html`)

- Preserve the approved 24 photographic plates, approximately **36-second** sequence, camera/mask composition and its ordering. Do not replace with new AI imagery or a static substitute.
- Preserve the final “The Third Era” / “Exhibition” / “Enter Below” title treatment and small subtly outlined ENTER control. The pill draws slowly, remains accessible, and navigates to `entrance.html`.
- Use `installation/cinema-original.css`, `installation/installation.css`, `homepage.css` and `installation/installation.js` as the existing cinematic system. Its responsive 3D scaling must fit the whole scene at phone/tablet/laptop/desktop sizes.
- Keep compact language/music controls as on the approved entrance. Music remains user-initiated. Pause motion appropriately when hidden; reduced-motion viewers can enter without waiting.
- New pages must not replay this opening film **unless the user explicitly asks**. They inherit the **same artistic and quality rules**, not an unsolicited duplicate cinematic sequence.

## C. Existing editorial overview-specific rules (`entrance.html`)

- Preserve the three illustrated era doors in their present order, imagery, approved copy, link destinations and intended hierarchy. Wide view: aligned triptych; phone: deliberate stacked/compact cards as defined by CSS; tablet: matched crop/label proportions. Maintain the existing header and footer only on published content pages.
- Intro copy, the **SVG three-branch JEW-HATRED framework**, three era disclosure cards and closing CTA must be accessible. Framework typography belongs to the same Caslon/Source system as page headings and body text.
- Trigger the diagram when it enters the viewport. Branch paths, arrowheads, era labels and captions resolve in a measured sequence; show a complete static diagram when JS is blocked. Captions/lines must be legible on small widths with no overlap.
- Three door images zoom subtly over **5.5 seconds**; the card, titles, subtitles and captions lift on hover/focus. Sections and sentences land as the reader scrolls.
- The work-in-review variants remain in `entrance.html`, `ru/entrance.html`, `he/entrance.html`, `overview-refinements.css` and shared `exhibit.js`. The English visible text remains unchanged in the draft; the translations are editorial drafts pending review.

## D. New page architecture — pages 03–22

- **Exactly 20 blank content slots**, numbered `page-03.html` through `page-22.html`, are reserved under `pages/`, `ru/pages/`, and `he/pages/`: **60 actual HTML files, representing 20 pages in three language versions**.
- Each file is a **valid blank HTML page** with an intentionally empty `<main>`. No visible copy, placeholder, artwork, footer, header, nav, CTA or sample content is allowed. A neutral browser-tab title and accessibility-only labels are permitted.
- Each uses the same **central** CSS and JS files: `exhibit.css`, `responsive.css`, `overview-refinements.css`, `exhibition-page-shell.css`, and `exhibit.js`. Shared edits propagate to the 20 future pages. The shell CSS only establishes blank canvas and screen-safe layout; it does not add new visual content.
- Each locale uses an HTML `<base>` path to resolve shared assets from the repository root, and has language metadata and matching noindex state. Never include a film replay or duplicate the 24 photographs on blank pages.
- When content is approved for a reserved slot, preserve the page's shared stylesheet/script references and its locale mirrors, change its `data-page-state` to `content` in all three languages and populate all three with **approved** text. The checker then compares structure across mirrors; it does **not** author or approve translations.
- Keep blank-page links out of navigation until the specific page is ready. When activated, add approved titles, canonical/hreflang, accessible image labels and licenses as part of that page's review.

## E. Mechanical verification (required)

Run `node tools/validate-exhibit-pages.mjs` after any edit. GitHub Actions runs this validator on PRs/branch pushes. It checks the number and naming of slots, locale mirrors, empty-main constraint for reserved pages, HTML class and base paths, required shared CSS/JS, noindex metadata, document structure and language parity. **A passing validator is not a substitute for visual QA or editorial approval.** For cinematic and editorial source-specific behavior, see `EXHIBIT_REQUIREMENTS.md`, `QA_REVIEW_2026-10-23.md`, and `LANGUAGES.md`.
